출고 웨이브 전략
규칙 하나가 주문을 작업 묶음으로 바꾸는 과정

창고는 주문 1건이 아니라 웨이브(작업 묶음) 단위로 할당→피킹→출고를 진행한다. 웨이브 전략은 "어떤 주문을 어느 웨이브에 넣을지"를 조건식으로 정의해 편성을 자동화하는 규칙이다. 아래 내용은 소스코드(OutbWaveServiceImpl, LodisStgyService)와 Company/dbData 운영 덤프로 검증했다.

진입점OutbWaveServiceImpl.stgyExec / stgyAutoExec
공통 엔진LodisStgyService.apply() — 필터로만 사용
규칙 저장소TWM_SG_STGY 3계층
판정 결과출고상태 100 → 200 (웨이브 편입)

1 · 목표

이 전략이 존재하는 이유

주문을 하나씩 고르는 수작업 편성을 규칙으로 대체하고, 이후 모든 출고 공정의 작업 단위를 확정한다.

자동 편성

"일반출고 & 1편 배차는 1편 웨이브로"처럼 규칙을 미리 정의하면, 조건에 맞는 주문이 자동으로 웨이브에 묶인다. 담당자의 개별 선택이 필요 없다.

배차·작업 단위 분리

차량편수(FLTNO), 출고유형(일반·반품·기타)별로 작업을 분리해, 같은 차수에 실릴 주문만 함께 할당·피킹된다.

후속 공정의 입력 확정

재고할당(전략 22)은 웨이브 단위로 실행된다. 웨이브 편성은 곧 "이 묶음으로 오늘 출고작업을 시작한다"는 선언이다.

4가지 전략유형(입고제약 11 · 입고적치 12 · 출고웨이브 21 · 재고할당 22) 중 웨이브는 공통 엔진을 가장 단순한 형태 — 주문 필터로 쓴다. 로케이션 추천이나 수량 분할 없이, "이 주문을 이 웨이브에 넣을지 말지"만 판정한다.

2 · 데이터 구조

전략 3계층이 웨이브에서 갖는 의미

전략설정 화면(WMSSG0001L)이 저장하는 3개 테이블이 웨이브에서는 각각 이렇게 읽힌다.

TWM_SG_STGY 전략 마스터 웨이브 1개 = 전략 1개

STGY_TYP_CD='21'로 식별. STGY_SEQ가 자동실행 시 웨이브 생성 순서가 되고, 전략명이 웨이브명(전략명_출고일)의 재료가 된다.

TWM_SG_STGY_APLY 적용전략 적용구분 '10' 생성단위만 사용 APLY끼리는 OR

한 전략에 APLY_NO를 여러 개 달면 대안 조건이 된다 — 하나만 통과해도 그 주문은 편입된다.

TWM_SG_STGY_COND 적용조건 무엇을 · 어떻게 · 어떤 값과 비교할지 같은 APLY 안에서는 AND

COND_CRTR_CD(조건기준) + COND_CMPR_CD(비교연산자, C01515) + COND_VAL(값). 한 적용전략의 조건은 전부 만족해야 통과한다.

조건기준이 주문 컬럼으로 풀리는 공통코드 체인

조건기준 코드가 주문 데이터의 어떤 컬럼과 비교되는지는 공통코드 4단 체인으로 해석된다 (TwmSgStgy.selectCondList가 조인으로 수행, twmSgStgy.xml:275).

3 · 실행 과정

자동실행 한 사이클

stgyAutoExecOutbWaveList() 기준. 선택실행은 ②에서 화면 선택한 웨이브·전략 1건만 처리하고, "이미 실행된 웨이브" 재실행과 "대상주문 0건"을 추가로 차단하는 점만 다르다.

1

금일 미생성 전략 선별 getNotCreatedWaveStgyCdList

전체 '21' 전략에서 오늘 이미 웨이브를 만든 전략을 MINUS로 제외한다. 자동실행을 하루 두 번 눌러도 중복 생성이 없는 이유.

2

전략마다 웨이브 마스터 생성 TWM_OB_WAV_M

웨이브번호 채번 → INSERT. 웨이브명은 전략명 + "_" + 출고일 (예: 일반출고 1편 웨이브_20241015), 진행상태 200.

3

전략조건 존재 검증 getStgyCondition

조건이 하나도 없으면 "웨이브 전략조건이 존재하지 않습니다" 오류로 중단 — 조건 없는 전략은 실행 자체가 거부된다.

4

웨이브 대상주문 조회 getOutbWaveTargetList

  • 출고 디테일 진행상태 100 — 아직 웨이브 미편성
  • 보류 제외 (HLD_YN ≠ 'Y') · 마감 제외 (CLOS_YN ≠ 'Y')
  • 출고예정일 = 웨이브의 출고일
5

주문 1건마다 lodisStgyService.apply() — 조건 게이트

적용전략(APLY)을 순서대로 시도하고, 각 APLY의 조건을 전부(AND) 검사한다. 첫 통과 시 콜백을 트랜잭션으로 실행하고 그 주문의 판정을 끝낸다.

통과 → 편입
  • WAV_LN_NO 채번 → TWM_OB_WAV_D INSERT
  • 출고 디테일 상태 100 → 200
  • 출고 마스터 상태 갱신
  • OMS 주문상태 동기화 (updateSoCoStatus)
전부 불통과 → 잔류
  • 주문은 상태 100 그대로
  • 다음 전략(다음 웨이브)의 후보로 남는다
  • 모든 전략에서 탈락하면 미편성 주문으로 화면에 계속 노출

편성 경로는 넷

선택실행stgyExecOutbWaveList :302

화면에서 웨이브 행 + 전략을 선택해 실행. 디테일이 이미 있으면 재실행 거부.

자동실행stgyAutoExecOutbWaveList :403

금일 미생성 전략 전부에 대해 웨이브 생성 + 편입을 일괄 수행.

전략 웨이브생성saveOutbWaveMstListByStgy :524

마스터만 만들어 두고, 편입은 이후 선택실행으로.

수동 편성saveOutbWaveDtlList :175

전략 미적용 — 담당자가 주문을 직접 추가. 상태 체크만 수행한다.

5 · 덤프에서 발견한 특이점

실무에서 조심할 것들

덤프 데이터를 훑으며 확인된, 문서에는 없는 실제 운영 상태.

1

전략 이름과 조건이 어긋난 데이터가 존재한다

S000001/C000001의 전략은 이름과 실제 조건이 서로 꼬여 있다. 전략명은 표시용일 뿐 실행은 오직 TWM_SG_STGY_COND 값으로 결정되므로, 화면에서 이름만 보고 실행하면 의도와 다른 주문이 편입된다.

전략이름실제 조건
OWV0001반품출고 웨이브일반출고(010) AND 1편
OWV0002일반출고 1편 웨이브일반출고(010) AND 2편
OWV0003일반출고 2편 웨이브반품출고(020)
2

APLY = OR, COND = AND

적용전략을 여러 개 달면 "둘 중 하나만 맞아도 편입"(공통 엔진이 첫 통과 시 콜백 후 종료, LodisStgyService.java:199), 한 적용전략 안의 조건들은 전부 만족해야 한다. S000006 OWV0002의 "(010 AND 2편) OR 기타출고(070)"가 실제 사용례다.

3

전략 실행보다 수동 편성이 더 많다

웨이브 디테일 82건 중 전략 실행(stgyAutoExec…)으로 생성된 건 13건, 수동 추가 (saveOutbWaveDtlList)가 58건. 수동 편성은 조건 검사를 거치지 않으므로 "전략 조건과 안 맞는 주문이 웨이브에 들어있는" 상황이 정상적으로 존재할 수 있다.

4

자동실행은 하루 1회 기준으로 멱등하다

getNotCreatedWaveStgyCdList가 오늘 이미 생성된 전략을 MINUS로 제외하므로 중복 생성이 없고, 전부 생성돼 있으면 "금일 웨이브전략이 모두 존재 합니다" 오류가 난다.
