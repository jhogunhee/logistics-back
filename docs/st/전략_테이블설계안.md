## 1. 설계 원칙 — 최우선 요구 2가지가 테이블에 강제하는 것

### 1.1 "전략마다 고유한 로직" → 로직을 DB에 넣지 않는다

실행 메타데이터(하위 그룹, 입력유형, 값 그룹, 비교할 컬럼, 실행기 식별자)를 공통코드 체인에 **데이터로** 넣으면 다음이 전부 가능해지고, 무엇 하나 DB가 막아주지 않는다:

- 구현이 없는 옵션도 화면에서 등록 가능 → 등록 즉시 실행 예외
- 실행기가 빈 껍데기여도 등록 가능 → 조건이 무조건 통과
- 비교할 컬럼 매핑이 비어도 등록 가능 → 등록은 되는데 비교가 일어나지 않음

새 설계에서 DB가 저장하는 것은 **"무엇을 선택했고 파라미터가 무엇인가"** 뿐이다. 실행 로직, 선택지 목록(Descriptor), 조건 필드 → 값 추출 매핑(필드 레지스트리 enum)은 전부 코드가 소유한다. 화면 폼은 메타데이터 API(코드 레지스트리에서 파생)로 렌더링하므로, **구현 없는 옵션은 화면에 아예 나타나지 않는다.**

> **주의: 이 프로젝트의 `code_group`/`code_detail`을 전략 선택지 저장에 쓰지 않는다.** 그것이 바로 위 함정으로 되돌아가는 길이다. 공통코드는 조건 "값" 목록(optionSource — 예: UOM, TEMP_ZONE)에만 쓴다.

### 1.2 "관리자 화면 설정" → 테이블 구조 = 화면 편집 단위

| 화면에서 하는 조작 | 저장 형태 |
|---|---|
| 개별 추가/삭제/순서변경(drag&drop) 하는 단위 — 검수 규칙, 적치 단계, 할당 슬롯 | **행** (`srt_seq` 보유) |
| 그 단위에 통째로 붙어 저장·검증되는 값 묶음 — 파라미터, 조건 목록, 정렬 기준 목록 | **jsonb** (저장 시 서버가 ParamSpec/필드 레지스트리로 검증, 실패는 저장 거부) |

D4 결정에 따라 **"잠깐 끄기" 상태는 없다.** 규칙·단계·전략을 실행에서 빼려면 삭제한다. 삭제 전 정의는 `stgy_rvsn` 스냅샷에 남아 있으므로, 화면은 리비전 목록에서 "이 리비전으로 복원" 기능으로 재등록을 지원한다 — 시험용 제약이 남아 전체 입고를 막는 사고는 삭제로 대응하고, 되돌리기는 리비전이 담당한다.

jsonb 채택이 무결성 포기가 아닌 이유: 이 프로젝트는 이미 "참조 무결성은 애플리케이션 책임"(FK 0건)이다. 조건·파라미터 검증 책임을 서비스에 두는 것은 같은 철학의 연장이고, 대신 DB는 구조 수준 방어(CHECK·UNIQUE·부분 유니크)를 최대한 가져간다 — §3의 제약 참고.

### 1.3 유형별 분리의 근거 — 범용 3계층으로는 의미를 표현할 수 없다

하나의 범용 「적용전략」 테이블에 행을 여러 개 두면, 그 "여러 행"의 논리 결합자가 유형마다 달라진다:

| 유형 | APLY 여러 행의 의미 | 전략 선택 방식 |
|---|---|---|
| 웨이브 | 행끼리 **OR** | 전부 순회, 각각 웨이브 생성 |
| 할당 | **역할 분담** (슬롯별 실행기) | 대상에 맞는 전략 1건 확정 |
| 적치 | 위치 × 방식 **조합** | 적용대상 매칭 + 순서대로 1건 |
| 검수 | 전량 **AND** 실행 | 선택 없음 |

하나의 범용 테이블은 이 넷 중 무엇도 스키마로 보장하지 못한다. 유형별 테이블로 나누면 각 테이블의 제약(단일 슬롯 유니크, 조건 0건 거부 CHECK 등)이 그 유형의 의미를 직접 표현한다.

| 테이블 | 추가 컬럼 | 의미 |
|---|---|---|
| `putaway_task` | `ptawy_stgy_id`, `rvsn_no` (둘 다 nullable) | NULL = 수동 지시 |

## 3. 테이블 상세 (DDL 초안)

컬럼명은 §7의 사전 등재를 전제로 한다. 감사 컬럼 4종(`created_at`/`created_by`/`updated_at`/`updated_by`)은 전 테이블 공통이라 생략 표기.

### 3.1 stgy_rvsn — 리비전 스냅샷 (공용)

```sql
CREATE TABLE stgy_rvsn (
    stgy_rvsn_id BIGINT      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    stgy_typ     VARCHAR(10) NOT NULL,   -- INSP | PTAWY | WAV | ALOC
    stgy_id      BIGINT      NOT NULL,   -- 유형별 헤더 PK (느슨한 참조, FK 없음)
    rvsn_no      BIGINT      NOT NULL,   -- 전략별 1부터 증가
    snpsht       JSONB       NOT NULL,   -- 헤더 + 하위 구성 전체 직렬화
    CONSTRAINT uq_stgy_rvsn UNIQUE (stgy_typ, stgy_id, rvsn_no),
    CONSTRAINT ck_stgy_rvsn_typ CHECK (stgy_typ IN ('INSP','PTAWY','WAV','ALOC')),
    CONSTRAINT ck_stgy_rvsn_no CHECK (rvsn_no >= 1)
);
```

- 전략 저장(생성·수정)마다 1행 추가, append-only. `created_at`/`created_by`가 곧 저장 시각/저장자.
- 유형별로 나누지 않는 이유: 읽기 전용 스냅샷이라 유형별 컬럼 차이가 없다 (재설계안 3.5 그대로).
- 실행 결과(웨이브·지시·할당)에 `stgy_id + rvsn_no`를 기록하면, 이후 정의가 바뀌어도 "그때 왜 그렇게 판정됐는지"를 스냅샷으로 재구성할 수 있다.

### 3.2 stgy_exec_log — 실행 로그 (공용)

```sql
CREATE TABLE stgy_exec_log (
    stgy_exec_log_id BIGINT      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    stgy_typ         VARCHAR(10) NOT NULL,
    stgy_id          BIGINT      NOT NULL,
    rvsn_no          BIGINT      NOT NULL,
    trgr_typ         VARCHAR(10) NOT NULL,  -- MANUAL | AUTO | PREVIEW
    tgt_ref          VARCHAR(30),           -- 웨이브번호·입고번호 등 (inv_hist.rfn_doc_no와 같은 느슨한 참조. 새 컬럼이므로 ref 표기)
    rslt_smry        VARCHAR(200),          -- "대상 12건 중 편입 9건"
    dcsn_trc         JSONB,                 -- 건별 {대상, 결과, 탈락사유:[{조건, 실제값, 기대값}]}
    CONSTRAINT ck_stgy_exec_log_typ  CHECK (stgy_typ IN ('INSP','PTAWY','WAV','ALOC')),
    CONSTRAINT ck_stgy_exec_log_trgr CHECK (trgr_typ IN ('MANUAL','AUTO','PREVIEW'))
);
CREATE INDEX ix_stgy_exec_log_stgy ON stgy_exec_log (stgy_typ, stgy_id, created_at);
CREATE INDEX ix_stgy_exec_log_ref  ON stgy_exec_log (tgt_ref);
```

- 검수는 산출물이 결과 행이 아니라 "차단"이라 실행 흔적이 남지 않는 유형이다. 이 테이블이 그 공백을 메우는 **필수** 테이블이다 — "왜 차단/탈락했나"를 조건 단위로 보여주는 관리자 요구의 근거 데이터.
- PREVIEW도 같은 구조로 기록하되 저장은 선택. 보존 기간 정책(예: PREVIEW 7일, 실행 로그 90일)은 운영 단계에서 배치로 — v1 테이블 설계에는 반영하지 않는다.

### 3.3 insp_plcy / insp_plcy_rule — 검수

```sql
CREATE TABLE insp_plcy (
    insp_plcy_id BIGINT       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    stgy_nm      VARCHAR(100) NOT NULL,   -- 표시용. 실행에 사용하지 않는다
    last_rvsn_no BIGINT       DEFAULT 1 NOT NULL,
    ...
);
-- [D8 확정] 전역 1행은 서비스가 검증한다 (2행째 생성 요청 거부). DB 상수식 유니크는 두지 않는다.

CREATE TABLE insp_plcy_rule (
    insp_plcy_rule_id BIGINT      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    insp_plcy_id      BIGINT      NOT NULL,
    srt_seq           INTEGER     DEFAULT 0 NOT NULL,
    rule_cd           VARCHAR(30) NOT NULL,        -- 레지스트리 code: LOT_DATE_REVERSE | SHELF_LIFE_PCT ...
    para              JSONB       DEFAULT '{}' NOT NULL,  -- ParamSpec으로 검증된 값 (예: {"minPercent": 30})
    CONSTRAINT uq_insp_plcy_rule UNIQUE (insp_plcy_id, rule_cd)
);
CREATE INDEX ix_insp_plcy_rule ON insp_plcy_rule (insp_plcy_id);
```

- **`prty`(우선순위)를 두지 않는다.** 검수는 "선택되는" 전략이 아니라 규칙 전부가 AND 실행되는 유형이다. 선택 순서 컬럼이 있으면 화면이 거짓말을 하게 된다 — "여러 개 만들면 하나가 골라진다"는 오해를 부른다.
- **규칙 끄기 = 행 삭제** (D4). 삭제 전 구성은 정책 리비전 스냅샷에 남으므로 복원 가능하다.
- 같은 규칙 2건 등록 금지(`uq_insp_plcy_rule`): SHELF_LIFE_PCT 2건은 AND라 더 엄격한 쪽 하나와 동일 — 의미 없는 중복을 DB가 거부.
- C10(역순제한)처럼 기준값이 필요 없는 규칙과 D02(% 필수)의 차이는 **컬럼이 아니라 각 규칙의 ParamSpec이 흡수**한다. 기준값 nullable 컬럼을 만들지 않는다.
- 제조일자 기준과 유통기한 기준은 같은 값을 다른 쪽에서 재는 것이라 `SHELF_LIFE_PCT` 하나로 통합 (재설계안 4.2).

### 3.4 ptawy_stgy / ptawy_stgy_stg — 적치

```sql
CREATE TABLE ptawy_stgy (
    ptawy_stgy_id BIGINT       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    stgy_nm       VARCHAR(100) NOT NULL,
    prty          INTEGER      DEFAULT 0 NOT NULL,   -- 낮을수록 우선. 적용대상 매칭 동률 시 선택 순서
    tgt_cond      JSONB        DEFAULT '[]' NOT NULL, -- 적용대상 [{fld,op,vals}] — 비면 전체 매칭
    unt_splt_yn   BOOLEAN      DEFAULT FALSE NOT NULL, -- 입수 단위 배수 절사 (낱개 혼적 방지)
    loc_srt       JSONB        DEFAULT '[]' NOT NULL, -- 후보 정렬 [{"field":"PIKNG_PRTY","dir":"ASC"}]
    last_rvsn_no  BIGINT       DEFAULT 1 NOT NULL,
    ...
);

CREATE TABLE ptawy_stgy_stg (
    ptawy_stgy_stg_id BIGINT      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    ptawy_stgy_id     BIGINT      NOT NULL,
    srt_seq           INTEGER     NOT NULL,
    mthd_cd           VARCHAR(30) NOT NULL,  -- FIXED_LOC | SAME_PROD_LOC | EMPTY_LOC (레지스트리)
    mthd_para         JSONB       DEFAULT '{}' NOT NULL,
    loc_cond          JSONB       DEFAULT '[]' NOT NULL, -- 후보 로케이션 범위 (존, 온도대 등)
    line_cond         JSONB       DEFAULT '[]' NOT NULL, -- 이 단계를 시도할 입고라인 조건
    ...
);
CREATE INDEX ix_ptawy_stgy_stg ON ptawy_stgy_stg (ptawy_stgy_id);
```

- **카티전 곱 → 명시적 단계 목록** (재설계안 5.1). 관리자가 실행 순서를 화면에서 그대로 읽는다. 곱으로 표현되던 조합은 단계를 그만큼 나열하면 동일 — 표현력 손실 없음.
- 재설계안의 `PutawaySplitPolicy` 4개 필드 중 **현행 스키마에서는 1개만 남는다** (§5.2 참고):
  - `defaultMaxLoadQty` 삭제 — `loc.max_qty`가 STORAGE에 NOT NULL 강제(`ck_loc_storage_capacity`)라 "MAX 미설정 = 999999" 문제가 구조적으로 이미 해결돼 있다.
  - `countPendingMoves` 삭제 — "적재가능 = max_qty − 현재고 − 미완료 지시 잔량"은 `loc.max_qty` 주석과 `ix_ptwy_task_open_loc` 인덱스가 전제하는 **불변식**이지 전략 옵션이 아니다. 끌 수 있게 만들면 기존 회계가 깨진다.
  - `skipWhenBelowOneCase` 삭제 — `unt_splt_yn`이 켜져 있으면 입수 몫 0인 로케이션은 배정 0으로 자동 스킵된다. 별도 플래그는 잉여.

### 3.5 wav_stgy — 웨이브 (테이블 1개)

> **[2026-08-03 개정 — 구현본과의 차이]** 아래 초안의 `wav_nm_ptrn`은 **두지 않는다.**

> 이미 날짜를 담는다(`WV-20260803-001`). 웨이브명이 필요해지면 `outb_wave.wav_nm` 신설이

CREATE TABLE wav_stgy (
    wav_stgy_id  BIGINT       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,

### 3.6 aloc_stgy / aloc_stgy_slot — 할당·분배

```sql
CREATE TABLE aloc_stgy (
    aloc_stgy_id BIGINT       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    stgy_nm      VARCHAR(100) NOT NULL,
    prty         INTEGER      DEFAULT 0 NOT NULL,
    tgt_cond     JSONB        DEFAULT '[]' NOT NULL,  -- 적용대상 — 비면 전체 매칭
    last_rvsn_no BIGINT       DEFAULT 1 NOT NULL,
    ...
);

CREATE TABLE aloc_stgy_slot (
    aloc_stgy_slot_id BIGINT      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    aloc_stgy_id      BIGINT      NOT NULL,
    slot_typ          VARCHAR(15) NOT NULL,
    srt_seq           INTEGER     DEFAULT 0 NOT NULL,  -- 다중 슬롯(필터·제약·분배) 내 순서
    cmpnt_cd          VARCHAR(30) NOT NULL,            -- 슬롯 타입별 레지스트리 구현체 code
    para              JSONB       DEFAULT '{}' NOT NULL, -- 예: MULTI_SORT의 [{field,dir}], 분배량 단위
    cond              JSONB       DEFAULT '[]' NOT NULL, -- 예: 우선분배 대상 선별 조건
    ...
    CONSTRAINT ck_aloc_slot_typ CHECK (
        slot_typ IN ('INVN_FLTR','RSTRCT','QTY_PLCY','INVN_SRT','ODR_SRT','DSTRB')
    )
);
CREATE INDEX ix_aloc_stgy_slot ON aloc_stgy_slot (aloc_stgy_id);
-- 단일 슬롯(수량정책·재고정렬·주문정렬)에 2건 등록을 DB가 거부
CREATE UNIQUE INDEX uq_aloc_stgy_slot_single ON aloc_stgy_slot (aloc_stgy_id, slot_typ)
    WHERE slot_typ IN ('QTY_PLCY','INVN_SRT','ODR_SRT');
```

- 슬롯 6종은 할당이 실제로 하는 일을 역할로 쪼갠 것이다: 재고위치→`INVN_FLTR`(다중·순서) · 출고제약→`RSTRCT`(다중) · 출고수량→`QTY_PLCY`(단일) · 재고할당순서→`INVN_SRT`(단일, 다중 기준은 para로) · 주문순서→`ODR_SRT`(단일) · 분배→`DSTRB`(다중·순서). 목적지(to) 로케이션은 지금 고를 것이 하나뿐이라 슬롯으로 만들지 않는다 — 요건이 확정되면 그때 추가한다.
- **분배는 별도 전략 유형이 아니라 슬롯이다.** 할당 중 부족과 피킹확정 부족, 두 무대에서 같은 구성이 그대로 재사용되기 때문이다.
- 분배량 단위와 대상 선별은 성격이 달라 저장 위치를 나눈다 — 같은 슬롯 행의 `para`(단위) / `cond`(대상)로 자리를 명확히 하고, 화면에서는 한 카드로 함께 보여줘 오독을 막는다.
- 필수 슬롯(`INVN_FLTR`·`QTY_PLCY`·`INVN_SRT`) 누락 검증은 행 부재를 CHECK로 표현할 수 없으므로 **저장 서비스가** 한다.

### 3.7 기존 테이블 변경

> **1차 구현 보류 (2026-08-02):** `putaway_task`는 스키마에만 있고 현행 코드가 쓰지 않는다(적치는 지시 없이 즉시 MOVE — `PutawayService`). 1차에서 적치 전략은 추천만 하므로 추적은 `stgy_exec_log`가 담당하고, 아래 `putaway_task` 변경은 지시 기반 전환 시 함께 적용한다. `outb_*` 변경은 2차(웨이브·할당)에서. 상세는 `전략_프로세스정의서.md` §3.1, `전략_테이블설계서.md` 머리말.

```sql
-- putaway_task: 이 지시를 만든 전략·리비전. NULL = 수동 지시
ALTER TABLE putaway_task ADD COLUMN ptawy_stgy_id BIGINT, ADD COLUMN rvsn_no BIGINT;
ALTER TABLE putaway_task ADD CONSTRAINT ck_ptwy_task_stgy
    CHECK ((ptawy_stgy_id IS NULL) = (rvsn_no IS NULL));

-- outb_wave: 이 웨이브를 만든 전략. NULL = 수동 생성
ALTER TABLE outb_wave ADD COLUMN wav_stgy_id BIGINT, ADD COLUMN rvsn_no BIGINT;
ALTER TABLE outb_wave ADD CONSTRAINT ck_outb_wave_stgy
    CHECK ((wav_stgy_id IS NULL) = (rvsn_no IS NULL));

-- outb_order: 웨이브 편입 출처. NULL = 미편성. 기존 편성분은 마이그레이션에서 MANUAL로 채움
ALTER TABLE outb_order ADD COLUMN wav_reg_typ VARCHAR(10);
ALTER TABLE outb_order ADD CONSTRAINT ck_outb_order_wav_reg CHECK (
    (wav_id IS NULL AND wav_reg_typ IS NULL)
    OR (wav_id IS NOT NULL AND wav_reg_typ IN ('STGY','MANUAL'))
);

-- outb_alloc: NULL = 현행 붙박이 FEFO 또는 수동
ALTER TABLE outb_alloc ADD COLUMN aloc_stgy_id BIGINT, ADD COLUMN rvsn_no BIGINT;

```

`outb_order.wav_reg_typ`의 근거: 조건으로 표현하기 어려운 묶음은 결국 수동으로 편성하게 된다. 금지 대상이 아니라 **가시화** 대상이다 — 화면에서 "전략 조건과 안 맞는 주문이 웨이브에 있음"을 구분 표시한다.

## 4. 조건(FieldCondition) 저장 형식

jsonb 안의 조건 1건은 다음 구조로 통일한다 (적용대상 `tgt_cond`, 웨이브 `cond_grp`, 적치 `loc_cond`/`line_cond`, 슬롯 `cond` 전부 동일):

```json
{ "fld": "STORE", "op": "IN", "vals": ["ST-0001", "ST-0002"] }
```

- `fld`: 도메인별 필드 레지스트리 enum의 code. **값을 꺼낼 컬럼이 없는 조건은 만들지 않는다** — 시작은 현행에 실존하는 필드만: 출고 쪽 `STORE`(점포)·`ODR_DE`(주문일)·`TMP_ZON`(상품 경유 온도대), 입고 쪽 `ODR_DVSN`(발주구분)·`VNDR`(벤더) 정도. 필드 추가 = enum 상수 추가 → 화면 자동 노출, 스키마 변경 없음.
- `op`: `EQ | NE | IN | NOT_IN | GE | LE | BETWEEN | LIKE` (enum). 연산자별 값 개수(BETWEEN=2, IN=1..n)는 저장 시 검증 — "실제값과 조건값을 거꾸로 넘김"·"같은 값끼리 비교해 항상 참" 류의 버그를 타입으로 차단.
- 저장 시 서버 검증: 필드 code 실존, 그 필드가 허용하는 연산자인지, 값이 optionSource 목록에 있는지. 실패는 저장 거부.

## 6. 프로젝트 규칙과의 충돌 — 결정 기록 (2026-08-02 확정)

### 6.1 [D4·확정] 사용여부 컬럼 전면 금지 유지 — 전략에도 `actv_yn` 없음

- 충돌 지점: `vendor` 주석·`migration-drop-us-yn.sql`의 "us_yn을 이 프로젝트의 어느 테이블에도 두지 않는다" vs 재설계안의 활성/비활성 토글.
- **결정: 금지 원칙을 유지한다.** 전략·규칙·단계·슬롯을 실행에서 빼려면 **물리삭제**한다. "지운 것도 쓰는 것도 아닌" 중간 상태를 전략에도 만들지 않는다.
- 재설계안이 활성 플래그로 풀려던 문제들의 대체 해법:
  - "테스트 제약 잔존 → 전체 입고 차단" → 문제 규칙을 삭제한다. 삭제 직전 구성은 `stgy_rvsn` 스냅샷에 있으므로 잃는 것이 없다.
  - "되돌리기" → 화면의 리비전 목록에서 "이 리비전으로 복원"(스냅샷을 새 저장으로 재생) 기능이 담당한다. 복원도 새 리비전을 만든다 — 이력은 항상 전진.
  - 구현체 은퇴(`deprecated`)는 데이터가 아니라 **코드 레지스트리 Descriptor의 속성**이므로 이 결정과 무관하게 유지된다.

### 6.2 [D5·확정] 테이블 접두 — 유형별 도메인 접두 + 공용 `stgy_`

- `insp_` / `ptawy_` / `wav_` / `aloc_` + 공용 `stgy_`(리비전·실행로그). `CLAUDE.md` 접두 목록에 추가한다.

### 6.3 [D8·확정] 검수 정책 전역 1행 — 서비스 검증만
