# 구현 전 설계 스냅샷

기능을 만들기 전에 「무엇을 할 것인가」를 정리한 문서들이다. **찍은 시점 그대로 두고 갱신하지 않는다.**

## `docs/design.md`와 어떻게 다른가

| | 담는 것 | 갱신 |
|---|---|---|
| `docs/design.md` | **지금** 이렇게 되어 있고 왜 그런가 | 설계가 바뀌면 함께 고친다 (번복 경위까지 적는다) |
| 여기 (`specs/`, `plans/`) | 만들기 **전에** 이렇게 하기로 했다 | 안 한다 — 그 시점의 기록이다 |

**설계의 주인은 언제나 `docs/design.md`다.** 여기 적힌 것과 코드가 어긋나면 코드와 `design.md`가 맞고 이쪽이 낡은 것이다. 두 벌을 유지하려 들면 어느 쪽이 최신인지 흐려지므로, 갱신하지 않는 쪽을 규칙으로 못박는다.

그런데도 남겨 두는 이유는 `design.md`가 담지 못하는 것이 있어서다.

- **일부러 하지 않기로 한 것** — 인증 설계의 「화면·버튼 단위 권한 편집, 역할 만들기 화면, 리프레시 토큰, 회원가입은 하지 않는다」 같은 결정. 안 만든 것은 현재 상태 문서에 남을 자리가 없다
- **쪼갠 방식** — 반품입고 계획서는 태스크 15개로 나눠 에이전트가 하나씩 구현한 그 계획이다. 결과가 아니라 진행 방식의 기록
